# v3.12.0 — Bilibili dual subtitles, and on-device speech recognition for videos without captions

**Source update on `main`.** The packaged GitHub release remains v3.9.0. Use the [current source ZIP](https://github.com/aolingge/yt-dual-subs/archive/refs/heads/main.zip) or a checkout. [Install guide](../../README.md#install) · [中文](#中文)

This source release carries two independent additions. They are separate on purpose: the Bilibili adaptation is one change you can review and revert on its own, and the local recognizer is another.

## Bilibili: Chinese videos with German subtitles

The same extension now serves both YouTube and Bilibili. On a Bilibili video page the German translation is the **top** line and the Chinese original is the **bottom** line, both from the same caption segment and both following the video clock. See [BILIBILI.md](../BILIBILI.md) for the full supported/unsupported list.

- **A small adapter instead of a fork.** `site.js` answers the platform questions the rest of the code asks — which site is current, the video identity, the playing `video` element, the overlay host, the native caption segments, the player's bottom inset, and the page's navigation events — and holds the per-site settings tables. Subtitle rendering, translation, styling, playback sync and the study tools are the unchanged shared code. `bilibili-page.js` is the page-world reader, mirroring `inject.js`'s role.
- **Cookie-free caption reading.** The reader reuses the subtitle list the player already fetched and the caption file the player already downloaded, watching the player's own requests rather than inventing a new one. When it needs the site's metadata endpoint it uses the page's ordinary session, never reads, copies or exports cookies, and adds no logic to get around a login, membership or access restriction. A missing track is reported as `need_login` or `no_track` after a bounded number of retries, never as an endless spinner.
- **Track choice by language and metadata, not by name.** A user-picked track wins; otherwise a human Chinese track outranks an auto-generated one, and Simplified outranks Traditional. Simplified, Traditional and auto-generated Chinese tracks are all recognised.
- **Millisecond cue conversion, verified by evidence.** Units are decided from the data (`tStartMs`/`dDurationMs` mean milliseconds; a non-integer start means seconds), empty and invalid entries are dropped, duplicates are collapsed, and the 1:1 cue mapping is kept so the existing sentence grouping still applies. Word times are never invented, and a long stretch of speech is never merged into one segment.
- **The part is part of the video identity** (`BV…#pN`), so two parts of one video can never share a caption cache. The isolated world re-derives the same key, because a content script cannot read page variables.
- **Per-site settings.** Bilibili's target language and line order are stored under their own keys and default to **Chinese → German, translation on top**. Changing Bilibili to German does not touch the user's YouTube setting, and no upgrade resets existing preferences.
- **Loading and translation stay separate.** Chinese appears as soon as it arrives, the current segment is translated first, following segments are prefetched through the existing queue, and the German line is updated when it returns. The Chinese stays visible when a translation is slow or fails, and the previous sentence's German is never shown for the current one. Switching video, part, track or target language cancels the old work and rejects its answers, so a stale translation cannot overwrite a new segment.
- **Honest states, not one spinner.** No track, captions not yet loaded, request failed, currently inaccessible and loaded-with-translation-in-progress are distinguished in the popup, and each states what to do next.
- **Local SRT import as the practical fallback.** A UTF-8 `.srt` file can be imported for the current video **and part**, replaced, or unbound. It rides the same cue, translation and sync pipeline, and is kept in extension-local storage — the file is never uploaded; only the text of the segments being translated is sent to the translation service, which is the provider already in use.
- **Chinese follow-along, labelled for what it is.** Chinese is the spoken language, so the highlight runs on the Chinese line, segmented by word (not by spaces) through `Intl.Segmenter`. Bilibili caption files carry sentence times, so the highlight is the approximate one and the video labels it as such. The German line is shown as a whole segment; no word-by-word German highlight is manufactured from Chinese word positions, because the two languages order their words differently.
- **No guessed platform selectors.** The native caption text is read from the player's subtitle container and the caption button is found by scanning for a caption-shaped `aria-label`/`title`, because the control-bar class names cannot be verified from the player bundle.
- `manifest.json` gains only the two `www.bilibili.com/video/*` content-script entries — no `<all_urls>`, and no new host permission beyond the translation endpoint already in use.

## On-device speech recognition for videos that have no captions

Built in parallel with the Bilibili work and independent of it.

- The popup gains an **On-device speech recognition** card. It is available only after the page has confirmed that the current video has **no** caption track: a readable track, a failed load, an unloaded page and an unknown state all block the start, because a second copy of subtitles the user already has is worse than none.
- Capture is the current tab's audio only, starts on an explicit click, and runs through an offscreen document so closing the popup does not end it. The video stays audible.
- Audio goes only to a **local** bridge on `127.0.0.1`; nothing is uploaded. The extension itself calls no cloud service.
- Recognised captions arrive in the same German-above-Chinese shape as a page track, timed from the media position the page reports — not from the moment the model finished — and the popup labels them as recognised rather than as the uploader's captions.
- A seek or a playback-rate change rebases the timeline and drops captions measured before the jump; switching video or part ends the session, and the next video has to be started again because its own caption state decides whether recognition is the right answer.

## Verification

The **312 source tests in 26 files** pass. New Bilibili and import cases cover caption conversion and unit detection, part identity, per-platform settings isolation and the popup's platform handling, stale-request rejection, track preference and the reason vocabulary, the SRT parser and its per-part binding.

A separate Edge with its own throwaway profile and the extension loaded unpacked drove the real path:

| Check | Result |
| --- | --- |
| Real Bilibili video with a readable Chinese track | German on top, Chinese below; a human Chinese track chosen; cue times in milliseconds |
| Controlled `bilibili.com/video` page | Human track preferred over an auto-generated one; German above Chinese; Chinese split into words with the labelled approximate follow-along |
| Only an auto-generated Chinese track | Selected and read |
| Captions but no Chinese track | Reported as *has captions, none is Chinese* |
| No caption track at all | Reported as *no Chinese track — import an SRT file* |
| Pause and a playback-rate change | The line holds at the paused time; a seek at 2× shows the new sentence |
| Switching part | `…BV1xx411c7mD#p2` → `…#p1`, each part loading its own cues |
| A file bound to another part | Ignored on `?p=1`; its own text appears on `?p=2`, translated |
| Layout in a viewport-sized container | The overlay stays inside the player and keeps rendering |
| YouTube regression | Overlay attached to `#movie_player`, `ytp-button` toggle inside `.ytp-right-controls`, `ytds-active` |

**Not verified.** Entering real fullscreen could not be exercised in the headless browser used for the check, so what stands verified there is the guarantee fullscreen rests on — the overlay is a child of the player and stays inside it when the container grows to the whole viewport — not the browser's fullscreen transition. A seek issued while the player was paused did not visibly take effect in that browser. Also unverified: switching parts on a live multi-part video, the player's fullscreen transitions on the live player, the waiting/`need_login` path against a signed-in session, native-caption restoration on the live page, and YouTube caption text in the same headless run. The controlled page supplies only the network answers, so it says nothing about live caption availability. Treat Bilibili support as verified for the ordinary case only.

The recognition path was verified by the pass that runs the shipping bridge over real HTTP with the models on disk and pushes a real speech sample through it in 100 ms chunks at 22.05 kHz, including a Chinese video with no captions and German audio that must not be translated into German.

Reload the extension in its existing unpacked folder, then refresh open YouTube and Bilibili tabs. Speech recognition additionally needs the desktop bridge; the extension does not install it.

## 哔哩哔哩：中文视频显示德语字幕

同一个扩展现在同时服务 YouTube 与 B 站。在 B 站视频页，**德语译文在上、中文原文在下**，两行属于同一个字幕片段，都跟随视频时间。完整的支持与未支持范围见 [BILIBILI.md](../BILIBILI.md)。

- **加适配层，不复制整套插件。** `site.js` 回答其余代码提出的平台问题——当前是哪个站点、视频标识、实际播放的 `video` 元素、覆盖层挂在哪个容器、原生字幕片段、播放器底部留白、页面导航事件——并保存按站点区分的设置表。字幕渲染、翻译、样式、播放同步和学习工具都是未改动的共享代码。`bilibili-page.js` 是页面环境里的读取模块，对应 `inject.js` 的角色。
- **不碰 Cookie 的字幕读取。** 读取模块复用播放器已经取回的字幕列表和播放器已经下载的字幕文件，监听播放器自身的请求，而不是另造一套。需要站点元数据接口时，用页面自身的正常会话；不读取、不复制、不导出 Cookie，也不添加任何绕过登录、会员或访问限制的逻辑。没有字幕轨时，会在有限次重试后报告 `need_login` 或 `no_track`，不会一直是转圈的“加载中”。
- **靠语言标识与元数据选轨，不靠名称。** 用户明确选择的轨优先；否则人工中文轨优先于自动生成轨，简体优先于繁体。简体、繁体与自动生成的中文字幕都能识别。
- **按证据判断单位的毫秒转换。** 单位由数据本身判断（`tStartMs`/`dDurationMs` 表示毫秒，开始时间非整数表示秒），空片段与非法时间被丢弃，重复项合并，并保留一一对应的片段映射，使原有的断句逻辑继续生效。不虚构词时间，也不把很长一段讲话合并成一个片段。
- **分 P 属于视频标识的一部分**（`BV…#pN`），因此同一视频的不同分 P 不可能共用一份字幕缓存。隔离环境会用同样的规则重新推导该标识，因为 content script 读不到页面的 JavaScript 变量。
- **按站点分开的设置。** B 站的目标语言与行序使用独立的键，默认**中文 → 德语、译文在上**。把 B 站改成德语不会影响用户的 YouTube 设置，升级也不会重置已有偏好。
- **加载与翻译分开。** 中文字幕一到就显示，优先翻译当前片段，后续片段通过现有队列预取，德语返回后更新对应行。翻译慢或失败时中文仍然可见，翻译未就绪时不会显示上一句的德语。切换视频、分 P、字幕轨或目标语言会取消旧任务并拒绝其返回结果，旧译文不会覆盖新片段。
- **区分状态，而不是一个转圈。** 没有字幕轨、尚未加载、请求失败、当前不可访问、已加载且正在翻译，这些状态在弹窗里各有说明，并告诉你下一步该做什么。
- **本地 SRT 导入作为实用补充。** 可以为当前视频**与分 P**导入 UTF-8 `.srt`，也可以替换或解除绑定。导入字幕走同一条字幕、翻译与同步流程，保存在扩展本地存储里——文件本身不会上传；只有被翻译片段的文本会发送给翻译服务，与现有做法一致。
- **中文跟读，如实标注。** 中文是实际发音的语言，因此高亮跑在中文行上，使用 `Intl.Segmenter` 按词切分（不是按空格）。B 站字幕文件只有句子时间，所以这是近似跟读，画面里会明确标注。德语行按整个片段展示；不会用中文词的位置去制造逐词德语高亮，因为两种语言的词序不同。
- **不猜平台选择器。** 原生字幕文本从播放器的字幕容器读取，字幕按钮通过扫描带字幕语义的 `aria-label`/`title` 找到，因为播放器包里的控制栏类名无法核实。
- `manifest.json` 只增加两条 `www.bilibili.com/video/*` 的 content script 条目——没有 `<all_urls>`，也没有在已用翻译接口之外新增主机权限。

## 无字幕视频的本机语音识别

与本轮 B 站适配并行完成，两者互相独立。

- 弹窗新增**本机语音识别**卡片。只有在页面确认当前视频**没有**字幕轨之后才可用：有可读字幕轨、字幕加载失败、页面未加载完成、状态未知都会被拦下，因为给用户已有的字幕再来一份，比没有更糟。
- 只采集当前标签页的音频，必须手动点击才开始，并运行在 offscreen 文档里，因此关闭弹窗不会中断。视频照常有声。
- 音频只发送到 `127.0.0.1` 上的**本机**桥接程序，不会上传；扩展自身不调用任何云端服务。
- 识别出的字幕与页面字幕轨同样是“德语在上、中文在下”的结构，时间取自页面报告的画面位置（而不是模型返回的时刻），弹窗会标明这是识别结果，而不是上传者提供的字幕。
- 拖动进度或改变倍速会重设时间基准并丢弃跳转前测得的字幕；切换视频或分 P 会结束会话，下一条视频必须重新开始，因为它自己的字幕状态才决定识别是否合适。

## 验证

**26 个文件的 312 项源码测试**全部通过。新增的 B 站与导入用例覆盖：字幕转换与单位判断、分 P 标识、按站点设置隔离与弹窗的平台处理、过期请求拒绝、选轨优先级与原因词汇、SRT 解析与按分 P 绑定。

另用独立 Edge（独立临时配置、以解压方式加载扩展）跑通了真实路径：

| 检查项 | 结果 |
| --- | --- |
| 有可读中文轨的真实 B 站视频 | 德语在上、中文在下；选中人工中文轨；时间为毫秒 |
| 受控 `bilibili.com/video` 页面 | 人工轨优先于自动生成轨；德语在上中文在下；中文按词切分并显示已标注的近似跟读 |
| 只有自动生成的中文轨 | 正常选中并读取 |
| 有字幕但没有中文轨 | 报告“有字幕，但没有中文字幕轨” |
| 完全没有字幕轨 | 报告“没有中文字幕轨——可导入 SRT” |
| 暂停与倍速 | 暂停时字幕停在停顿时间；2 倍速下拖动进度后显示新的句子 |
| 切换分 P | `…BV1xx411c7mD#p2` → `…#p1`，每个分 P 各自加载字幕 |
| 绑定到另一个分 P 的字幕文件 | 在 `?p=1` 被忽略；在 `?p=2` 显示自己的文字并翻译 |
| 容器放大到整个视口 | 覆盖层仍在播放器范围内并继续渲染 |
| YouTube 回归 | 覆盖层挂在 `#movie_player`，`ytp-button` 按钮位于 `.ytp-right-controls`，`ytds-active` |

**未验证。** 用于检查的无头浏览器无法真正进入全屏，因此那里验证的是全屏所依赖的保证——覆盖层是播放器的子节点，并在容器放大到整个视口时仍在范围内——而不是浏览器自身的全屏切换。在该浏览器中，暂停状态下发出的拖动进度没有可见效果。同样未验证：真实多 P 视频的分 P 切换、真实播放器的全屏进出、已登录会话下的等待/`need_login` 路径、真实页面上的原生字幕恢复，以及同一次无头运行中 YouTube 的字幕文本。受控页面只提供网络应答，因此不能说明线上字幕的实际可得性。请把 B 站支持理解为常规情形已验证。

语音识别路径由“用真实 HTTP 启动发行版桥接程序 + 磁盘上已有模型 + 真实语音样本以 22.05 kHz、每 100 毫秒一块推入”的验证覆盖，其中包括一个无字幕的中文视频，以及必须不被翻译成德语的德语音频。

在原来的解压目录重新加载扩展，再刷新已打开的 YouTube 与 B 站标签页。语音识别还需要桌面端桥接程序，扩展不会替你安装它。
