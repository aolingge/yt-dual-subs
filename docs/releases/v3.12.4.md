# 3.12.4 — 音频输入状态与采集生命周期

本机源码与可加载包更新，2026-10-04；没有公开发布。

- 本机识别面板新增音频输入状态：已暂停、等待、有信号、持续静音、未收到数据、处理暂停、等待视频时间位置。
- 播放中连续约八秒未出现达到 16 位 PCM 量级的信号，提示持续静音或信号过低；这是提示，不是故障判定，不自动停止、不更改视频音量。正常短停顿不显示这条提示。
- 播放中约三秒未收到采集数据，与“收到的音频都是静音”分开提示。暂停、恢复、跳转和倍速产生的时间线变化会重置观察窗口。
- 修复状态返回遗漏：队列、P95 与模型提示现在确实返回给面板。后台恢复时同时恢复输入状态。
- 采集音轨结束时停止处理、释放音轨及音频上下文，保留已经显示的字幕。旧录音的迟到回调不会写入新会话或恢复运行状态。
- 修复重复“没有原生字幕”消息清除识别字幕与校正的问题。原生字幕状态变成未知或出错时，停止识别并拒绝迟到结果，包括首句尚未返回的启动阶段。
- 诊断浏览器继续使用独立配置及 `--mute-audio`；用视频自身 `captureStream()` 检查解码后信号，未替换真正 tabCapture 输入。

## 验证范围

新增十四项回归测试；扩展测试共 394 项通过。真实浏览器诊断证实中文输入提示及队列数可见，解码后源信号非零，但 tabCapture 仍为零。禁止将诊断检查通过称为真实语音采集通过。替代录音输入的识别／翻译检查单独记录。

使用：重载扩展并刷新视频页；不需升级模型或安装额外服务。本版本没有改变识别模型及其准确性评估结论。参见[使用说明](../RECOGNITION_SETTINGS.md)。
