# v3.9.2 — Earlier subtitle startup and fewer duplicate requests

**Source update on `main`.** The packaged GitHub release remains v3.9.0. Use the [current source ZIP](https://github.com/aolingge/yt-dual-subs/archive/refs/heads/main.zip) or a checkout. [Install guide](../../README.md#install) · [中文](#中文)

- Start the subtitle interface when the player exists, without waiting for the rest of YouTube to finish parsing. Safely wait for missing root/player nodes and honor saved disabled preferences.
- Share pending original requests across repeated startup/config messages. Retain the latest nonce check and allow a fresh player token to recover a stuck request.
- Reuse pending and successful whole-track translations within the current video. After HTTP 429, pause new whole-track translation requests for 20 seconds across configs, targets, tokens, and navigation. Original loading and Google fallback stay independent.
- Retain v3.9.1's configurable highlighting, subtitle recovery, and durable batched preference saves. No new permission or dependency is needed.

All **155 source regression tests** passed. In isolated Edge with a controlled 3-second parser delay, the previous source showed both lines at about **3.15s**, while the updated source showed them at about **0.16s**, before `DOMContentLoaded`. This measures removed extension startup waiting, not live YouTube or translation-service latency. A separate controlled check returned empty originals and HTTP 429 translations: four original attempts issued only one translated-track request, and native preview plus Google fallback still displayed both lines, with no page errors. Separate timing script paths preserve spoken-word highlighting in both execution worlds.

An anonymous live-video check encountered empty HTTP 200 original responses, HTTP 429 translated responses, and a YouTube playback error. That check cannot verify complete live-video playback or identify a user's earlier failure without its logs.

Reload the extension in its existing unpacked folder and refresh open YouTube tabs to activate the updated scripts.

## 中文

**这是 `main` 分支的源码更新。** GitHub 发行包仍为 v3.9.0；请使用[最新源码 ZIP](https://github.com/aolingge/yt-dual-subs/archive/refs/heads/main.zip)或 Git 克隆。[安装说明](../../README.zh-CN.md#安装)

- 播放器出现就启动字幕界面，无需等整个页面解析完成；注入时根节点和播放器尚未出现也能安全等待，并保留已关闭扩展的设置。
- 重复初始化或配置消息共用未完成的原文请求，仍只接受最新请求结果；播放器提供新令牌时可恢复卡住的请求。
- 当前视频的整轨译文会复用未完成或成功的请求。遇到 HTTP 429 后暂停新整轨翻译请求 20 秒，改变设置、语言或视频、刷新播放器令牌都不会绕过等待；原文与 Google 备用翻译独立工作。
- 保留 3.9.1 的可调高亮、字幕自动恢复与可靠设置保存；无需新增权限或依赖。

全部 **155 项源码回归测试**通过。在独立 Edge 中故意将页面解析延迟 3 秒时，旧版约 **3.15 秒**才显示双语字幕，新版约 **0.16 秒**就显示，在页面解析完成前接管。此结果用于验证移除扩展自身的启动等待，并非真实 YouTube 或翻译服务的速度保证。另一个受控检查模拟原文空响应与译文 HTTP 429：原文尝试 4 次，整轨翻译只请求 1 次；原文预览与 Google 备用翻译仍显示双行，页面没有错误。两种运行环境使用独立的时间脚本路径，保留逐词高亮。

匿名真实视频检查遇到原文 HTTP 200 空响应、译文 HTTP 429 和 YouTube 播放器报错，因此未完成真实视频全流程验证；缺少用户故障时的日志，也不能确定先前故障的全部原因。

在原来的解压目录重新加载扩展，再刷新已打开的 YouTube 标签页，使新脚本生效。
