# 字幕性能检查 / Subtitle performance review

检查日期：2026-10-04；源码版本：3.12.6。

## 范围与结果

本轮聚焦播放、字幕显示、识别轮询、界面查询和测试体验。沿用现有工具，没有新增服务或依赖。以下复杂度结论来自实际代码路径；浏览器请求数量来自可重复的受控测试，不代表所有视频的总体速度提升百分比。

| 路径 | 检查发现 / 处理 | 验证方式 |
| --- | --- | --- |
| 播放中的词定位 | 逐个比较词时间改为二分查找；O(n) 比较改为 O(log n) | 90 词长句、多次前后跳转、真实间隙、全文标点的回归测试 |
| 近似跟读的语速 | 不再每句遍历全字幕来生成缓存戳；字幕列表身份与语言决定复用，人工修正和对齐使缓存失效 | 既有语速与音频时间测试、人工修正流程 |
| 识别空轮询 | 没有 segment 时不建立全字幕 Map、不复制、不排序；O(n) 表处理改为常量操作 | 5,000 条字幕的列表身份与删除记录回归测试 |
| 重复 / 过期识别修订 | 仍需按 ID 查找，但内容不变时避免复制和排序 | 同一回归测试覆盖过期与重复修订 |
| 删除后的迟到响应 | 识别任务直接保存合并后的列表，保留 WeakMap 删除记录 | 完整识别协议的删除、空轮询、旧结果重发回归测试 |
| 弹窗与学习页状态 | 同一标签页只共用正在执行的请求；刷新完成后恢复正常读取 | 实际 Edge 页面中 20 次并发慢刷新只发送 1 次查询；下一轮发送新的查询 |
| 后台学习页 | 隐藏时定时回调不发请求，显示时触发刷新 | 使用 `document.hidden` 和 `visibilitychange` 的现有界面代码路径；实际后台资源占用未单独量化 |
| 翻译请求 | 继续使用既有排队、当前句预取、429 冷却与迟到响应丢弃 | 既有 latency、translation、source-recovery 回归测试 |
| 字幕阅读 | 全句保留，标点保留，低于 120ms 的词不单独闪亮 | 德语标点、短词与播放回归测试；受控浏览器画面 |
| 高亮对比度 | 淡背景与旧版黑色文字组合不清楚；默认改白色，只迁移旧版完整默认配色一次，预览与播放器统一 | 自定义配色与后续修改保留测试；实际浏览器读取到白色文字 |
| 识别计算 | 沿用现有 VAD、质量设置、队列限流和不确定结果标记 | 配套桥接 Python 回归测试；语料结果见 ACCURACY.md |
| 收藏与存储 | 沿用稳定 ID、长度限制和数据迁移 | 既有 study-store 与 study-export 测试；本轮不扩展收藏功能 |
| 测试声音 | 独立 Edge 启动包含 `--mute-audio` | 浏览器实际命令行证据；没有测量扬声器声压 |

## 重跑

本轮完整 Node 测试通过 405 项，结构检查通过 336 个本地化键；配套识别桥针对性 Python 测试通过 91 项。综合界面验证通过 29 项，并检查实际浏览器命令中的静音参数。真实 Bilibili 页面最终取得 47 条原文字幕；真实 YouTube 页面只验证播放器挂载和按钮，没有取得可读字幕文本。全屏未实际进入，扩大视口的布局检查通过。

```powershell
node --test tests/*.test.cjs
node tools/check-extension.mjs
node tools/verify-study-security.mjs
node tools/verify-bilibili.mjs
```

`verify-study-security.mjs` 是已有综合界面验证脚本，包含字幕、学习与状态刷新检查；本轮没有增加安全功能。浏览器验证将真实站点和受控字幕分开报告。真实站点不提供可读字幕时，不能用受控结果替代该项。

## 仍未证实

- 当前机器真实无头 Edge `tabCapture` 可启动，但输入曾全零；本轮未解决或宣称解决。
- 用解码 WAV 输入验证后续识别链路，不等于验证标签页采集。
- 源数据无标点时，不自动猜测补写；须以人工参考语料评估自动标点方案。
- 未量化长期 CPU、内存、耗电或所有视频的帧率变化；不承诺统一百分比提升。
- 原生全屏、登录后字幕可用性和其他平台模型结果仍需对应环境证据。
