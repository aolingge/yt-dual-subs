# 识别准确性与推荐配置

核对日期：2026-10-04；以下语料基线测量对应扩展 3.12.2 和配套 Deutsch Overlay 源码桥。当前扩展为 3.12.6，后续字幕、配置和性能修复见各版更新记录；本轮没有重新测量或改写下面的识别指标。

## 2026-10-04：新增修复与实测

- 不再根据 Bilibili 网站或旧字幕语言强制指定语音语言。面板支持自动、中文、德语、英语，运行期间禁止更改；手动选择优先。
- 自动语言需两段独立且至少 2 秒的最终语句给出相同语言及不低于 0.8 的概率才确认；临时结果和同段修订不重复计数，跳转后清空证据。这是项目策略，不是经过标定的语言识别正确率。
- 使用 faster-whisper 已依赖的 PyAV/FFmpeg `AudioResampler`，保持各音频包之间的滤波状态；原实现会在每包重新创建重采样器，并存在 44.1 kHz 相位偏差及高频混叠。
- 对齐到原始输入坐标，流结束时刷出滤波尾部。丢包的零填充放在后续音频之前；末尾不足一帧的音频进入 VAD 后按实际长度截断，响应的接收范围包含真实尾部。
- 长静音后的临时/最终句定位保留实际预留音频起点；跳转后清空预留片段和语音检测上下文。
- 最终识别保留逐词时间，拒绝非有限、越界、反向、重叠的词时间。源词转换到视频时间，通过置信度下限 0.25 和完整文本匹配后用于原文跟读；面板明确显示“识别词时间，可能存在误差”。不将其套用于译文。
- 原文修订没有可用词时间时清空旧词时间，防止修订后的文本高亮沿用旧结果。

### 信号测量

1 秒正弦信号、相同源文件处理、丢弃两端各 500 个输出样本以排除边界效应：

| 输入与指标 | 原实现 | PyAV/FFmpeg |
| --- | ---: | ---: |
| 44.1 kHz 输入，440 Hz 与理想信号的 SNR | 20.40 dB | 93.27 dB |
| 44.1 kHz 输入，3 kHz 与理想信号的 SNR | 3.91 dB | 101.81 dB |
| 44.1 kHz 输入，10 kHz 的混叠输出 RMS | 0.7081 | 0.0000091 |

这些指标证明音频转换更忠实及高频抑制有效，不等于真实听写错误率的改善。

### 实际模型比较

使用本机 Whisper Small、CPU/int8、固定显式语言及 `condition_on_previous_text=False`。Google FLEURS（CC-BY-4.0）每种语言取测试归档中最先出现且匹配 `test.tsv` 的 3 段真人音频，分别模拟 44.1/48 kHz 输入。每组分母合并两种输入率，只有 3 个独立样本；不能视为总体统计。

旧流程：原重采样器、beam 3、无词时间。最终流程：PyAV、beam 3、词时间与 `hallucination_silence_threshold=1.0`。模型解码采用同一固定设置；比较包含多项变化，不能归因于单项。

| 语言及指标 | 旧流程 | 最终流程 |
| --- | ---: | ---: |
| 德语 WER | 3/124 = 2.42% | 2/124 = 1.61% |
| 英语 WER | 14/146 = 9.59% | 15/146 = 10.27% |
| 普通话原始 CER | 28/162 = 17.28% | 35/162 = 21.60% |

中文一个 44.1 kHz 样本从简体转成繁体，原始 CER 将字体差异计为错误；没有偷偷归一化或删除该样本。其他两个中文样本及 48 kHz 的该样本未变化。英语增加了一个单位错误。真人录音结果混合，不能宣称整体文字识别更准。另测了 3 段已知文本的 SAPI 合成语音：德语 WER 4.17%、英语 3.85%、中文 CER 0%，两个输入率前后相同。

候选 beam 5 也经过同组真人对比，没有带来一致的收益，最终保留 beam 3。词时间有实际显示用途，但未用人工逐词边界验证绝对时间误差。更大模型、噪声、音乐、多人交谈和术语仍需另行对照测量。

## 已修复的具体问题

- seek 或倍速变更后，立即清除旧音频队列和旧字幕；迟到的识别结果只能进入它所属的 timeline epoch。
- 同一句原文被模型修正后，旧译文失效；只有原文与原文语言一致时，后续修订才保留已有译文。
- 异常、缺失、反向时间戳和只有译文没有原文的识别结果被拒绝，不再被修正成时间零。
- 慢请求合并为至多一个待完成音频提交和一个字幕轮询，避免计时器不断积压请求。失败音频只在当前 epoch 重试。
- 停止识别先提交全部剩余音频，再通知桥结束、读取尾句并关闭会话；停止与建立会话同时发生也会关闭最终建立的会话。
- 音频对齐缓存同时检查逐词置信度下限 0.12 与整句平均值下限 0.25，与现有辅助程序保持一致。
- 配套 Deutsch Overlay 本机引擎将模型每个句子、每个词的相对时间转换成各自的样本偏移。此前同一音频块的多个句子会共用整个音频块的范围，丢失句子之间的定位。
- 识别字幕以音频块、流代次和句子序号保持稳定身份，模型修正句子起点后更新原句，避免按新时间额外追加重复字幕。

## 推荐配置及依据

| 场景 | 配置 | 依据与限制 |
| --- | --- | --- |
| 有原生字幕轨 | 跟读时间来源「自动」 | 优先字幕词时间与可靠的同语言匹配；无法可靠匹配时明确标为近似。 |
| 有字幕但词高亮不准 | 「音频对齐」，使用匹配的视频音频/本地文件与正确起始偏移 | 现有 CTC 辅助程序支持德语、英语。强制对齐可改善词定位，但不能纠正原字幕内容。 |
| 已确认无字幕 | 手动启动本机识别；保留现有 VAD 与 `condition_on_previous_text=False` | 本机引擎已启用这些选项。VAD 去除无语音部分，关闭跨片段文本条件可减少失败循环；均不保证零漏识别或零误识别。 |
| 追求更高文本准确率 | 先选择实际语音语言，再用目标领域的人工参考测量模型和解码设置 | 本轮小规模真人 WER/CER 与 beam 3/5 对比结果混合，最终保留 beam 3；不能保证更大的 beam 更准。 |

语音识别依然只接受当前视频/分 P 的 `absent` 状态。`unknown`、`checking`、有字幕、登录受限、下载错误均不能启动。识别源词时间不能当作德语译文的逐词时间。

## 如何判断真正提升

回归测试用于证明时间转换、修订合并、队列和会话生命周期正确，不能证明模型听写准确率。模型对比应使用固定且人工校对的中文、英语、德语样本，覆盖安静人声、背景音乐、长停顿、专有名词、多人交谈。比较中文 CER、其他语言 WER、句子起止误差与首句/尾句延迟；相同样本、硬件、模型和解码配置应保持可追溯。

浏览器验证中的受控媒体是静音 WAV 与固定字幕，它验证显示和播放同步，不测量真实语音听写。无头浏览器没有实际进入全屏时，报告必须列为未验证；播放器放大至视口的布局检查独立记录。真实 YouTube 页面如果受网络或播放限制，不能把页面打不开记作字幕通过。
